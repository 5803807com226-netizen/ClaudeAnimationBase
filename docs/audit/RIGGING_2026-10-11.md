# Character rigging on Windows: fixes and results, 11 Oct 2026

Run in the cloud with Chromium on software GL. The studio was driven through its own API, the same calls its buttons make. Your images in `assets/stories/stone_friends/` were only read, never changed; every rig works on a copy in `out/studio/rigs/<id>/`.

## 1. `UnicodeEncodeError: 'charmap' codec can't encode character '→'`

- **Cause.**
  - When Node runs Python through a pipe on Windows, Python's output uses the cp1252 encoding.
  - `rig_analyze.py` prints `→`, which cp1252 can't encode, so it crashes.
  - The same applies to `prop_analyze.py`, to `make_test_assets.py`, and to any Thai text.
- **Reproduced.** Running `PYTHONIOENCODING=cp1252 python rig_analyze.py … | cat` gives exactly this error on the old code.
- **Fix, in two layers.**
  1. Every Python tool (12 files) switches stdout and stderr to UTF-8 (`errors='replace'`, so it can never crash on output).
  2. Every Node program that starts Python sets `PYTHONUTF8=1` and `PYTHONIOENCODING=utf-8`, and its children inherit them: `studio/server.mjs`, `tools/pipeline.mjs`, `gen_assets.mjs`, `compile_plan.mjs` and `audit_windows.mjs`.
- **Verified.** The same command now prints the line and exits 0.

## 2. Why the dinosaur used `--template=human`

- The studio offered only the `human` template; I had limited it to that because the `quadruped` template crashes the engine. My audit script also used `human` for both characters.
- `human` expects a front-view figure with its arms and legs apart from the body. Dino is drawn from the side, with a tail and a head as wide as its body, so the human template cannot fit it.

## 3. New template: `biped_tail`

This template is for a two-legged character with a tail, seen from the side: cartoon dinosaurs, birds, kangaroos. It reuses the human skeleton the engine already animates and adds a `tail` bone, so the engine needed no rebuild.

**What it detects or places:**

| Joint | How it is found | Confidence |
|---|---|---|
| Facing direction | The heavier end of the upper body | — |
| Toes | Where the silhouette touches the ground | detected |
| Tail tip | The farthest point behind | detected |
| Head top | The top of the front part of the head | detected |
| Neck | Under the jaw: the chin is the lowest point of the front quarter | estimated |
| Chest, hips, legs | By proportion | estimated |
| Arms | Template guess | uncertain |

- **Rest angles kept as drawn (`keepBind`).** The engine treats every character's rest pose as a standing human, so it would pull Dino's spine and neck upright and put his head on top of his body. The rig now names the bones whose rest angle comes from the image instead (spine, neck, head, tail).
  - This is a 4-line, data-driven change in `src/action/rig.js`.
  - Existing human rigs are unaffected: the 33-preset test fixtures still pass 34 of 34 checks.
- **Joint editor (studio).**
  - The template list has "สัตว์ยืนสองขามีหาง หันข้าง (เช่น ไดโนเสาร์)", and picking an image with dino, rex, bird and similar in its name selects it.
  - A **"สลับขาหน้า/หลัง"** button swaps the near and far legs, because a single side view cannot tell which leg is in front.
  - Saving joints re-measures the capsules automatically.

### Taro (`taro_front.png`, `human`), unchanged from the previous audit

- **Automatic:** only 2 of 20 joints are within 40 px. Taro's head is about half his height, so the neck search finds a narrowing inside the hair (y 56 instead of about 565). The chest and shoulders follow it up into the head, and both legs are guesses.
- **Fully automatic, run by `tools/audit_windows.mjs --only=rig`:** **6/6 measured checks, but the picture is broken.** When Taro waves, pieces of his head and hair fly off with the arm. [frames](taro_dino_automatic.jpg) This is the clearest case of the checks passing while the rig is unusable.
- **After placing the joints in the editor:** 5/6 checks. Feet are on the ground (0.44 px), with no pops or jumps; one 1.67 px slide against a 1.5 px limit. Thin slivers of the old arms remain when the arms move. [frames](taro_human_edited.jpg)
- I did not change the human detector: it is what all 33 preset fixtures rely on, and a fix for chibi proportions risks breaking it. For Taro, place the joints in the editor.

## Still not production quality

Both characters need hand-placed joints. Even then, the seams (Dino's back), torn regions (Dino's belly) and leftover slivers (Taro's arms) come from cutting **one flat image** into parts.

The intended route for production is cut-out puppet parts (`tools/action/puppet.py`). Its ComfyUI driver, `tools/action/gen_character.mjs`, is referenced in the code but was never committed.

The measured checks (`verify.mjs`) test the skeleton, not the picture: Dino B passes 6/6 while the close-up shows the seam. Always look at the frames.
