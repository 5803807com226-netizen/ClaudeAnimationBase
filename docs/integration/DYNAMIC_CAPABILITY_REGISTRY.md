# Dynamic Capability Registry (proposal)

**Goal.** The Director plans only with capabilities that exist and are verified. A new preset becomes discoverable without edits to the Director prompt, the UI or the compiler.

## 1. Extend `definePreset` (backwards compatible)

Existing presets keep working. New, optional keys:

```js
definePreset('routeDraw', {
  label, about, defaults, run, demo,             // existing
  meta: {
    version: '1.0.0', category: 'map',            // camera | object | type | collage | map | chart | diagram | transition | character
    tags: ['route', 'path', 'journey', 'migration', 'trade'],
    assets: [{ param: 'data', type: 'route' }],   // what the compiler must resolve
    layers: ['overlay'], camera: 'world',         // world (moves with the camera) | screen (fixed)
    composable: true,
    params: {                                     // a small JSON-schema subset: type, min, max, enum, default
      at:  { type: 'number', min: 0 }, dur: { type: 'number', min: 0.1, max: 30 },
      color: { type: 'color' }, width: { type: 'number', min: 0.5, max: 20 }
    },
    fixture: 'tools/fixtures/capabilities/routeDraw.json'   // the preview or test spec
  }
});
```

Type presets (`kinetic.js`), collage layers, `objectTransition` and story templates register through the same `meta`. They do this through thin wrappers (`defineCapability`); their code is not rewritten.

## 2. Discovery

- `src/presets/manifest.json` lists the preset files and is generated by `node tools/capabilities.mjs --build`. `story.html` loads its list instead of hardcoding `<script>` tags, so a file dropped into `src/presets/` becomes known after the build.
- `node tools/capabilities.mjs --json > out/capabilities.json`:
  - loads the engine headless, reusing `tools/lib/harness.mjs`;
  - dumps every registered capability with its `meta`, aspects and status;
  - adds a catalog hash.
- AutoCinematic passes a compact catalog to Opus: only `id`, `category`, `about`, `tags`, `params` (names and ranges), `assets` and `status`. The full preset list is never pasted into the prompt.

## 3. Status (computed, never hand-set)

- `verified`: the capability's fixture passes `tools/capability_test.mjs`. That test renders it low-res in 9:16 and 16:9, measures motion and checks for console errors. The pass is recorded in `src/presets/verified.json` together with a hash of the capability's source, and any edit to the code clears it.
- `experimental`: the capability loads but has not passed. The Director sees it but may use it only when the mode permits.
- `PRESET_ASPECTS` and `TYPE_PRESET_ASPECTS` stay the aspect source of truth.

## 4. Compiler use

For each layer, the compiler resolves `cap` to the registry and validates `params` against the schema, merging in `defaults`. It resolves `assets` against the manifest and checks timing (`at + dur <= shot length`). On a miss, it looks for a verified alternative with the same `category` and overlapping `tags`, but only if `fallback` allows it. Otherwise the shot is marked `blocked`.

## 5. First capabilities needed for a map pilot

| id | category | notes |
|---|---|---|
| `mapView` | camera | d3-geo projection; animates center, zoom and rotation |
| `mapBase` | map | land, coastline and graticule from Natural Earth (`world-atlas`, vendored) |
| `routeDraw` | map | path along geodesic or sampled coordinates with a moving head |
| `territoryHighlight` | map | fill and outline pulse for a sourced polygon |
| `mapLabel` / `mapMarker` | map | live Thai or Latin text pinned to coordinates; collision-aware through the existing type layout |
| `timelineReveal` | diagram | dated ticks drawn in sync |
| `barGrow` | chart | sourced values only |

Already present and reusable: `cameraMove`, `objectReveal`, `popBounce`, `particleBurst`, `brushWipe`, `shapeMorph`, the type presets, collage layers and looks.
